# 겜소공 프로젝트 — 개발 지침

이 파일은 이 저장소에서 작업하는 Claude 세션이 매번 읽는 프로젝트 지침이다.
새 세션은 이 파일만 읽고도 맥락을 잡을 수 있어야 한다.

---

## 1. 프로젝트

- **과목**: 게임소프트웨어공학 (3학년 2학기), 한국공학대
- **목표물**: 쿼터뷰(아이소메트릭) 2.5D 실시간 렌더링 오픈월드 RPG
- **기반**: KPU 이택희 교수 `SimpleGame` 베이스 프로젝트
- **기술 스택**: C++ / OpenGL 3.3 / freeglut / GLEW / Visual Studio 2022 (v143, x64)
- **원격 저장소**: https://github.com/ldhsky/Game-Software-Engineering

### 디렉터리

```
BaseProject_SE/
  SimpleGame.sln
  SimpleGame/
    SimpleGame.cpp        진입점, GLUT 콜백 등록
    Renderer.h / .cpp     셰이더 컴파일, VBO, DrawSolidRect
    Shaders/              SolidRect.vs, SolidRect.fs
    Dependencies/         glew, freeglut 헤더와 lib
  Debug/ Release/         런타임 DLL (추적 대상 — 지우지 말 것)
```

## 2. 작업 방식 — 반드시 지킬 것

- **빌드와 실행 결과 확인은 사용자가 직접 한다.** Claude는 코드 수정까지만 하고,
  빌드를 대신 돌리거나 실행 결과를 검증하려 하지 않는다.
- 수정 후에는 **사용자가 무엇을 확인해야 하는지** 한 줄로 짚어준다.
  (예: "배경색을 바꿔봐야 clear 순서 수정이 눈에 보인다")
- 컴파일이 깨질 수 있는 변경(함수 시그니처, 언어 표준, 헤더 구성)은 **미리 경고하고 나눠서** 넣는다.
- 빌드 에러가 나면 사용자가 출력을 붙여준다. 그걸로 진단한다.
- 사용자는 UE5 블루프린트와 DirectX 12를 다뤄본 경험이 있다. 그래픽스 개념 설명은
  기초부터 하지 않아도 되고, DX12 대응 개념으로 설명하면 빠르게 통한다.

## 3. 저장소 규칙

- **`.gitignore`는 저장소 루트의 것만 유효하다.** `BaseProject_SE/gitignore`(점 없는 파일)는
  과거의 잔재이며 아무 효력이 없다. 무시 규칙을 추가할 일이 있으면 루트 `.gitignore`를 고친다.
- git 패턴에서 **후행 공백은 패턴의 일부**다. 절대 넣지 말 것.
- `Debug/`, `Release/` 아래의 `freeglut.dll`, `glew32.dll`은 **의도적으로 추적 중**이다.
  새로 클론한 사람이 바로 실행할 수 있어야 하므로 무시 목록에 넣지 않는다.
  반면 `x64/` 아래 산출물은 전부 무시 대상이다.
- **커밋은 Claude가 만들어도 되지만, 푸시는 사용자가 한다.** 작업 환경에 GitHub 자격 증명이
  없어서 `git push`가 인증 실패한다. 커밋만 만들고 사용자에게 알린다.
- 저장소가 **OneDrive 동기화 폴더 안에 있다.** OneDrive가 `.git` 내부를 동기화하다 인덱스를
  깨뜨릴 수 있다. `.git/index.lock`이 남아 git이 실패하는 경우가 있으니 잠금 파일 제거로 복구한다.
  (장기적으로는 동기화 밖 경로로 이전 권장)
- 소스 파일은 **UTF-8 with BOM**으로 저장한다. BOM이 없으면 MSVC가 한글 주석을 CP949로
  오해하고, 기존 파일 일부가 이미 CP949로 저장되어 깨져 있다.

## 4. 코드 규약

### 좌표계

베이스 프로젝트의 `DrawSolidRect`는 **픽셀 단위**로 위치와 크기를 받는다.
VBO 정점이 `±1/windowSize`이고 정점 셰이더가 `u_Trans.w`(size)를 곱하는 구조다.
`GetGLPosition`이 `x * 2/windowSize`로 NDC 변환한다.
→ `DrawSolidRect(0,0,0,4,...)`는 화면 중앙의 4픽셀 사각형이다. 안 보인다고 당황하지 말 것.

### 아이소메트릭 변환 (2:1 쿼터뷰)

```
screenX = (worldX - worldY) * (tileWidth  / 2)
screenY = (worldX + worldY) * (tileHeight / 2) - worldZ * heightScale
depth   = (worldX + worldY)
```

**`worldZ`(화면상 높이)와 `depth`(앞뒤 정렬)는 별개 개념이다.** 이 분리가 2.5D의 핵심.
역변환 함수는 월드→화면 함수와 **항상 한 쌍으로** 유지한다. 마우스 피킹, 타일 선택,
카메라 가시 범위 계산이 모두 역변환에 의존한다.

### 그리기 순서

`worldX + worldY` 기준 정렬 후 뒤에서 앞으로 그리는 **화가 알고리즘**을 채택한다.
깊이 버퍼 방식은 알파 블렌딩과 상충하므로 스프라이트 기반에서는 쓰지 않는다.
현재 코드는 `GLUT_DEPTH`를 요청하고 `GL_DEPTH_BUFFER_BIT`를 지우면서
`glEnable(GL_DEPTH_TEST)`는 하지 않는 어정쩡한 상태다.

### 스프라이트 기준점

**하단 중앙**을 기준점으로 한다. 현재 `DrawSolidRect`는 중심 기준이다.
쿼터뷰에서 캐릭터가 타일 위에 서려면 발밑이 기준이어야 한다.

## 5. 알려진 문제 (미해결)

우선순위 순. 고칠 때는 사용자에게 확인 방법을 함께 알려준다.

1. **셰이더 컴파일 실패가 성공으로 판정됨.** `Renderer::CompileShaders`가 실패 시 `return -1`
   하는데 반환형이 `GLuint`다. `0xFFFFFFFF`가 되어 `m_SolidRectShader > 0` 검사를 통과하고
   `IsInitialized()`가 true를 반환한다. → `return 0`으로 고칠 것.
2. **VAO가 없다.** `#version 330`을 쓰면서 VAO를 만들지 않는다. freeglut의 기본
   compatibility profile 덕에 동작하는 것이며, core profile로 바꾸면 즉시 깨진다.
3. **`glClear`가 `glClearColor`보다 먼저 호출된다** (`SimpleGame.cpp` RenderScene).
   매 프레임 이전 프레임의 색으로 지우고 있다. 배경색을 바꾸면 한 프레임 밀린다.
4. **`delete g_Renderer`가 실행되지 않는다.** `glutMainLoop()`는 반환하지 않는다.
   소멸자도 비어 있어 `glDeleteBuffers`/`glDeleteProgram`이 없다.
5. **`Idle`이 `RenderScene`을 직접 호출한다.** `glutPostRedisplay()`가 정석.
   델타 타임 개념이 아예 없어서 애니메이션을 넣으면 프레임률에 속도가 의존한다.
6. 매 드로우마다 `glGetUniformLocation`/`glGetAttribLocation` 문자열 조회 → 초기화 시 캐싱 필요.
7. `DrawSolidRect` 끝의 불필요한 `glBindFramebuffer(GL_FRAMEBUFFER, 0)`.
8. `char*` 매개변수에 문자열 리터럴 전달 (`ReadFile`, `CompileShaders`) → `const char*`로.
9. `AddShader`가 컴파일 실패를 호출자에게 알리지 않음 (로그만 출력). `glewInit()` 반환값 미확인.
10. 정점 셰이더가 `newPosition.z = 0`으로 z를 버린다. 2.5D에는 z 전달이 필요하다.

## 6. 아키텍처 진행 순서

오픈월드가 강제하는 제약 때문에 이 순서를 지킨다. 나중에 끼워넣기 어려운 것이 앞에 온다.

1. **좌표 변환 + 카메라** — 월드↔화면 변환 한 쌍, 카메라, 가시 범위 계산.
   카메라 없이 작성한 코드는 전부 다시 써야 하므로 최우선.
2. **텍스처 스프라이트 드로우 + 배칭** — 알파 블렌딩. 사각형만으로는 쿼터뷰를 확인할 수 없다.
   드로우 콜 하나당 사각형 하나 구조로는 타일맵을 못 버틴다 → 동적 VBO에 모아 한 번에 그린다.
3. **청크 타일맵** — 맵을 고정 크기 청크(예: 32×32)로 나눈다. 통짜 2차원 배열로 시작하면
   나중에 전면 수정이 된다. 카메라 주변 청크만 순회/렌더.
4. **프레임 루프와 입력** — 델타 타임, Update/Render 분리, 키 상태 배열(`glutKeyboardUpFunc` 필요).
5. 캐릭터 이동, AABB 충돌, 전투, 대화, 세이브/로드.

**세이브/로드는 초반 설계에 포함한다.** RPG는 게임 상태를 직렬화 가능한 형태로 유지해야 하며,
나중에 붙이려면 코드 전체를 뒤져야 한다.

## 8. 세계관 — 「등가의 장부」

상세 문서는 아티팩트로 관리한다. 서사 작업 시 먼저 읽을 것.

- 세계관 설정: https://claude.ai/code/artifact/4e055c6a-53e4-49d1-bbae-d7e6aa0b9473
- 메인 퀘스트 트리: https://claude.ai/code/artifact/00adda7c-c7e8-439d-b69c-48a03845a291

### 요약

중세 판타지, 다크한 분위기에 건조한 관료주의 유머. 핵심 주제는 **생명의 신비와 죽음의 의미**이며,
등가교환을 큰 축으로 삼는다 (강철의 연금술사에서 뼈대만, 코스믹 호러에서 축만 차용 —
원작 고유 요소는 쓰지 않는다).

- **값** — 무엇을 얻으려면 같은 무게를 내놓아야 한다. 지불은 가능하나 **산정은 인간이 못 한다.**
- **셈꾼** — 값을 산정하는 미지의 존재. 악의 없음, 협상 불가. 끝까지 보스로 등장시키지 않는다.
- **결손** — 값이 치러질 때 무엇이 빠져나갈지 고를 수 없다. 지불자가 아니라 지불자와
  이어진 세계가 나눠 낸다. 게임의 공포·수집물·시스템이 모두 여기서 나온다.
- **환산 길드** — 값을 미리 계산해준다고 주장하는 관료 조직. 유머의 유일한 원천.
- 3막 반전: 최초로 되살려진 것은 사람이 아니라 **세계 자체**. 결손은 분할 납부이며
  셈꾼은 추심원이었다.

### 톤 규칙

**유머는 인간 쪽에만 둔다. 셈꾼이 등장하는 장면에서는 유머·UI·음악이 전부 사라진다.**
이 분리를 지키지 않으면 다크 판타지가 무너진다.

### 세계관 ↔ 시스템 접점

- 능력 사용에 값이 붙는다 (마나 바 없음). 무엇이 빠져나갈지 사용 시점에 알 수 없다.
- 결손은 영구 누적 디버프이자 서사. **렌더러 차원에서 구현 가능한 종류**로 설계한다
  (화면에서 특정 색이 사라짐, 지도 일부가 지워짐 등).
- 오픈월드 탐험 보상 = 장부 페이지. 넓은 맵 문제를 서사로 흡수한다.
- 퀘스트 로그가 세계관 안의 물건이다 (플레이어는 기억되지 않으므로 전부 적어야 한다).

## 9. 범위에 대한 경고

오픈월드 RPG는 한 학기 개인 과제로 완주 불가능한 규모다. 목표는
**"오픈월드 RPG의 수직 슬라이스"** — 좁지만 끝까지 완성된 조각이며, 넓힐 수 있는 구조를
증명하되 실제로 넓히지는 않는다.

**최소 성립 조건**: 프롤로그 P2("누구세요?")와 3막 C3(셈꾼의 응답) 두 장면이 완성돼 있으면
세계관·시스템·톤을 전부 보여줄 수 있다. 학기말에 전체를 못 채워도 프로젝트는 성립한다.

범위를 늘리는 제안을 받으면, 이 안전선을 먼저 짚어줄 것.
